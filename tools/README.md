# tools/ — 診断・検証スクリプト

本番の自動更新には**関与しない**、手元で実行する調査用スクリプト置き場。
`.github/workflows/` からは呼ばれない。

## 収録スクリプト

| ファイル | 用途 | 終了コードで結論が出る |
|---|---|---|
| `diag_ais.py` | AISstream.io の疎通診断。ホルムズ bbox と全世界 bbox の対照実験 | 0=正常 / 10=bbox・カバレッジ問題 / 20=サービス側 / 30=接続・認証 |
| `diag_ais_coverage.py` | 全世界 bbox で受信し、**地理的に集計してカバレッジの実在を判定** | 0=ホルムズで受信 / 10=中東圏で受信 / 20=中東が完全空白 / 30=接続・認証 |
| `diag_gfw.py` | Global Fishing Watch API がホルムズの通航船を返すかの実現可能性検証 | 0=検出できた / 10=0件 / 20=認証 / 30=パラメータ不正 |
| `diag_vesselapi.py` | VesselAPI の無料枠でホルムズの通航船が取れるかの実現可能性検証 | 0=検出できた / 10=当該海域のカバレッジ無し / 20=API・アカウント側 / 30=接続・認証 |

いずれも**読み取り専用**（ファイルを書かない）。API キーは環境変数から読む。ハードコードしない。

## なぜ残してあるか

2026-09-01 の調査で、AISstream.io に**ペルシャ湾・ホルムズ海峡の受信局カバレッジが存在しない**ことが判明した
（全世界 bbox は60秒で3,467隻、ホルムズ bbox は180秒で0隻。最寄りの受信船まで約1,900km）。
この状態のまま 2026-04-15 から約4.5か月、`vessels_detected: 0` を書き続けていた。

**契約・実装の前にカバレッジを実測する**という手順を踏んでいれば防げた失敗であり、
`diag_ais_coverage.py` の手法（全世界受信 → 地理的集計）は次のデータソース選定で再利用できる。

新しい AIS ソースを検討する際は、**必ず無料枠・トライアルの範囲でホルムズ bbox の実測を行ってから**契約すること。

## AIS データソース選定メモ（2026-09-03 時点・未確定）

### 満たすべき要件

1. **ホルムズ海峡／ペルシャ湾の実カバレッジ**（地上 AIS だけでは届かない。衛星 AIS またはそれに準ずる補完が要る）
2. **「取得成功かつ0隻」と「取得失敗」をレスポンスから区別できること**
   （AISstream.io は WebSocket ストリーム型のため両者が同じ `0 / 0` になり区別不能だった。
   REST 型 API なら HTTP ステータス＋空配列で区別できる見込み。確度：高／未実測）
3. **日次1回の取得で足りる**（現行 cron は日次。リアルタイム性は要件外）
4. **公開サイトでの表示が利用規約上許されること**（ここが最大の制約）

### ライセンス上の注意（重要）

Datalastic の利用規約は、**生データ・API レスポンスをそのままの形で公開アプリケーションに表示すること**を禁じている。
一方で、**分析・可視化・ダッシュボード等の付加価値プロダクトの作成は認められている**（生データを露出させず、
サービスの代替として機能しない限り）。

当サイトの用途は個船情報ではなく**通航隻数の集計値の表示**であるため、許容範囲に入る可能性が高いが、
**これは条文の解釈であり確定ではない。契約前に提供元へ書面で確認すること**（確度：中）。
同種の条項は他の商用プロバイダにも存在するのが通例のため、候補ごとに同じ確認が要る。

### VesselAPI の制約（ドキュメント記載・2026-09-03 確認）

無償運用の最有力候補だが、採用前に踏まえるべき制約が5つある。

1. **API キーの有効期限は最長 90 日**（30/60/90 から選択）。無料プラン自体の期限ではなくキーの寿命。
   運用に乗せるなら必ず 90 日を選び、**90日ごとに再発行して GitHub Secret を更新する**必要がある。
   忘れると取得が黙って止まる — 今回の「4.5か月0隻」と同型の事故になるため、
   401/403 を受けたらワークフローを失敗させ、通知が届く状態を保つこと
2. **bbox 検索の time 窓は最大4時間**（`time.to - time.from` ≤ 4h）。
   日次1回（30コール/月）で取れるのは「1日の通航量」ではなく**ある4時間帯のスナップショット**。
   1日を通して数えるには 6回/日 × 30日 = 180コールとなり、無料枠150を超える
3. **`pagination.limit` は最大50**。輻輳海域ではページングが要り、1スナップショットで複数コールを消費する。
   月間コール数の試算は実測してから行うこと
4. **bbox の総スパン `|dLat| + |dLon|` は 4 度以内**（2026-09-03 に実測で判明。公開ドキュメントに記載なし。
   超えると `HTTP 400 / invalid_parameter` で、**クォータは消費されない**）。
   本番 `scripts/fetch_ais.py` の BBOX（lat 22-27 / lon 55.5-60.5）は**スパン和 10 度でそのままでは通らない**。
   同じ範囲を覆うにはタイル分割が必要で、2度×2度のタイルなら 9 タイル＝1回あたり9コール。
   日次でも月270コールとなり**無料枠150を超える**。
   無償で運用するなら、監視範囲を**ホルムズ海峡本体の1タイル**（`diag_vesselapi.py` の既定：
   lat 25.8-27.0 / lon 55.6-57.0、スパン和 2.6 度）に絞る前提になる
5. **bbox レスポンスに船種フィールドが無い**（`cog` / `heading` / `imo` / `latitude` / `longitude` /
   `mmsi` / `nav_status` / `sog` / `timestamp` / `vessel_name`）。
   現行の breakdown（tanker / cargo / other）はこのエンドポイントだけでは作れない。
   船種は MMSI ごとの別エンドポイントになり、隻数ぶんのコールを消費して無料枠が破綻する見込み

**衛星応答は月次クォータを消費せず、別枠の衛星クレジットで支払う**とドキュメントに明記されている。
無料プランに衛星クレジットが付くとは書かれていないため、無料枠で取れるのは地上 AIS のみと思われる。
ただし**ホルムズ海峡では実際にデータが返ることを実測で確認済み**（下記）。
`X-Data-Source` ヘッダは返ってこないため、地上／衛星の別は判別できない。

### 実測結果（2026-09-03・`diag_vesselapi.py`）

**ホルムズ海峡でカバレッジが存在することを確認した。AISstream.io の問題は解消する。**

| 時間窓 | 消費コール | ユニーク隻数 | 移動中（sog≧1kt） | 停泊・漂泊 | 月間試算 |
|---|---|---|---|---|---|
| API既定 | 3 | 21 | **5** | 16 | **90（無料枠内）** |
| 4時間 | 7 | 34 | 6 | 28 | 210（超過） |

**時間窓を4時間に広げてもコールが2.3倍になるだけで、移動中の船は5→6隻しか増えない。**
増分13隻はすべて錨泊船だった。4時間窓にコストを払う理由がない。

その他、実測で分かったこと:

- **返るのは「船のリスト」ではなく「位置報告のリスト」**。145レコードでユニークは21隻
  （1隻あたり平均7件）。`pagination.limit=50` は「50隻」ではなく「50メッセージ」。
  **取得側で MMSI による重複排除が必須**
- **失敗と0隻は構造的に区別できる**。不正キーは `HTTP 401 / invalid_api_key`、
  船のいない海域（南太平洋）は `HTTP 200 / vessels: []` で返る。
  → 依頼2の論点3で **3-C（三値化）が縮退せずに成立する**
- **クォータは成功リクエストのみ消費**（1コール=1）。401 と 400 は消費されない
- **返るフィールドは船ごとに可変**（`cog` / `heading` が欠ける船がある）。取得側の防御が要る
- 未文書フィールド `location` は GeoJSON Point（`[lon, lat]`）。緯度経度と重複し使い道なし
- 錨泊船が多いのは bbox 南西端にホル・ファッカン沖の錨泊地（lat 25.97 / lon 56.05 付近）が
  入っているため。除外もできるが、**危機時の錨泊待機の急増は封鎖の先行シグナル**として
  価値があるため残す

### 採用構成（2026-09-03 決定・規約確認待ち）

| 項目 | 内容 |
|---|---|
| データソース | VesselAPI 無料枠（150コール/月・カード不要） |
| 取得範囲 | ホルムズ海峡 bbox（lat 25.8-27.0 / lon 55.6-57.0、スパン和 2.6 度） |
| 時間窓 | API 既定（`time.from` / `time.to` を指定しない） |
| 頻度 | 日次1回 |
| 消費 | 3コール/回 × 30日 = **月90コール**（150に対し60の余裕） |
| 表示値 | 総隻数・移動中・停泊/漂泊の3値 |
| 費用 | **0円** |

**breakdown の設計変更**: 船種フィールドが無いため、現行の tanker / cargo / other は作れない。
**「移動中 / 停泊・漂泊」に差し替える**。船種別が要るなら推計側に残す。

**運用上の必須事項**: キーは最長90日で失効する。90日ごとに再発行して GitHub Secret を更新すること。
401/403 を受けたらワークフローを失敗させ、**黙って止まらない状態を保つ**。
